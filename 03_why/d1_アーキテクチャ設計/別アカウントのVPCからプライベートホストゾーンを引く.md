# 別アカウントの VPC から、プライベートホストゾーンを引く

- 出典：CloudTech SAP-2007（カテゴリ：分野1-ネットワーク接続戦略）
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.4 ネットワーク）
- 自分の解答：「関連付けの承認」と「開発アカウントにインバウンドエンドポイント」（不正解。後者が誤り）
- 関連：[プライベートホストゾーンの名前が引けない](プライベートホストゾーンの名前が引けない.md)、[オンプレとVPCで双方向に名前解決する](オンプレとVPCで双方向に名前解決する.md)

## 問題の要約（自分の言葉で）

Organizations 配下の複数アカウント環境。共有サービスアカウントにプライベートホストゾーンがあり、今は同じアカウントの VPC からしか引けない。
新しく作った開発アカウントの VPC からも引けるようにしたい。ゾーンやレコードはコピーしない。2つ選ぶ問題。

## 要件のキーワード

- 「別アカウントの VPC」「ホストゾーンはそのまま使う」→ **アカウントをまたいだ VPC の関連付け**
- 複製しない → 新しいゾーンを作る案や、コピーする案は外れる

## 正解

2段階で、**それぞれのアカウントで1回ずつ** 操作する。

1. **ゾーンを持っている側**（共有サービスアカウント）：`create-vpc-association-authorization` で「開発アカウントのこの VPC なら関連付けてよい」と **許可** を出す
2. **VPC を持っている側**（開発アカウント）：`associate-vpc-with-hosted-zone` で、共有サービスアカウントのゾーンに自分の VPC を **関連付ける**

## なぜ正解？

- プライベートホストゾーンは「関連付けた VPC の中からだけ引ける」もの。別アカウントの VPC も、関連付けさえすれば同じように引ける
- 他人のゾーンに勝手に関連付けられないように、**持ち主の許可 → VPC 側の関連付け** という2段階になっている
- この操作は **コンソールではできず、CLI / API / SDK のみ**
- 関連付けが済んだら許可は消してよい（消しても関連付けは残る）

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| RAM でプライベートホストゾーンを共有する | プライベートホストゾーンは **RAM で直接共有できない**。RAM で共有できるのは Resolver の転送ルールなど（下の補足も参照） |
| 開発アカウントに新しいゾーンを作り、エイリアスで委任 | 新しいゾーンを作るのは「複製しない」に反する。エイリアスレコードは AWS のリソース（ELB など）を指すもので、ゾーンの委任には使えない |
| 開発アカウントの VPC にインバウンドエンドポイントを作り、共有サービス側から転送 | インバウンドエンドポイントは **オンプレ → AWS** の入口。VPC 同士なら関連付けるだけで済み、エンドポイントは不要。しかも転送の向きが逆（引きたいのは開発側） |

## 自分がインバウンドエンドポイントを選んだ理由と反省

直前に Resolver エンドポイントの問題（SAP-2005、2006）を続けて解いたので、「別の場所から名前を引く ＝ エンドポイント」と連想した可能性が高い。
でもエンドポイントは **オンプレとの間** の話。**AWS の VPC 同士** なら、プライベートホストゾーンに関連付けるだけで済む。

## 「どこから引くか」で使うものが変わる

| どこから | 何を引く | 使うもの |
| --- | --- | --- |
| 同じアカウントの VPC | プライベートホストゾーン | VPC に関連付け ＋ DNS 属性2つ |
| **別アカウントの VPC** | プライベートホストゾーン | **許可（ゾーン側）→ 関連付け（VPC 側）** |
| オンプレ | プライベートホストゾーン | インバウンドエンドポイント |
| VPC | オンプレのドメイン | アウトバウンドエンドポイント ＋ 転送ルール |

## 補足：Route 53 プロファイル

VPC やアカウントがたくさんある場合は、**Route 53 プロファイル** という新しめの方法もある。
プライベートホストゾーンや転送ルールを「プロファイル」にまとめて **RAM で共有** すると、関連付けた VPC すべてに同じ DNS 設定が配られる。
この問題の選択肢は「ホストゾーンそのものを RAM で共有」なので誤りだが、「プロファイルを RAM で共有」なら成り立つ。混同しないように。

## 調べたこと

- [別アカウントの VPC をプライベートホストゾーンに関連付ける](https://docs.aws.amazon.com/ja_jp/Route53/latest/DeveloperGuide/hosted-zone-private-associate-vpcs-different-accounts.html)：
  - ゾーン側で許可 → VPC 側で関連付け。VPC ごとに許可が必要
  - コンソールでは操作できない（CLI / API / SDK）
  - 関連付け後は許可を消すことが推奨。消しても関連付けは残る
- [Route 53 プロファイル](https://docs.aws.amazon.com/ja_jp/Route53/latest/DeveloperGuide/profiles.html)：DNS 設定をまとめて、RAM で他のアカウントと共有できる

## 一言で言うと

- 別アカウントの VPC → **ゾーン側で許可、VPC 側で関連付け**
- Resolver エンドポイントは **オンプレとの間** だけ。VPC 同士では使わない
