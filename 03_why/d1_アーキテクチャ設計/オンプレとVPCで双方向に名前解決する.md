# オンプレと VPC で、双方向に名前解決する

- 出典：CloudTech SAP-2006（カテゴリ：分野1-ネットワーク接続戦略）
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.3 ハイブリッド、1.4 ネットワーク）
- 自分の解答：A（正解）
- 関連：[VPCからオンプレの社内ドメインを引く](VPCからオンプレの社内ドメインを引く.md)（SAP-2005）、[プライベートホストゾーンの名前が引けない](プライベートホストゾーンの名前が引けない.md)（SAP-2004）

## 問題の要約（自分の言葉で）

オンプレと Direct Connect でつながった環境。VPC の EC2 からオンプレの社内ドメインを引きたい。
同時に、オンプレのサーバーから VPC のプライベートホストゾーンも引きたい。DNS サーバーを自分で作ったりパッチを当てたりはしたくない。運用負荷は最小に。

## 要件のキーワード

- 「VPC → オンプレ」と「オンプレ → VPC」の **両方向**
- 「DNS サーバーの構築・パッチは避けたい」「運用負荷を最小」→ **マネージドの Route 53 Resolver エンドポイント**

## 正解

- A：**アウトバウンド**エンドポイント＋転送ルール（VPC → オンプレ）と、**インバウンド**エンドポイント（オンプレ → VPC）の両方を作る。オンプレの DNS サーバーは、AWS 側のドメインをインバウンドエンドポイントの IP へ転送する

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| B：EC2 に BIND を入れて転送用 DNS サーバーにする | 動くが、**DNS サーバーを自分で構築・パッチ当て**することになり、要件に反する |
| C：AD Connector に名前解決を中継させる | AD Connector はオンプレの Active Directory へ **認証を中継** するもの。プライベートホストゾーンの名前をオンプレへ返す仕組みではない |
| D：オンプレのゾーンをプライベートホストゾーンにコピーし、オンプレからは VPC の +2 を参照 | VPC の +2（Amazon の DNS）は **VPC の中からしか使えない**。オンプレから直接は問い合わせられないので、そのための入口としてインバウンドエンドポイントがある。ゾーンのコピーも二重管理になる |

## 一言で言うと

- 双方向の名前解決 → **インバウンドとアウトバウンドの両方**
- オンプレから VPC の +2 には届かない。だからインバウンドエンドポイントが要る
