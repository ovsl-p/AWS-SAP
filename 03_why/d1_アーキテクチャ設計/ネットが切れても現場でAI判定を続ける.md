# ネットが切れても、現場で AI の判定を続ける

- 出典：CloudTech SAP-2002
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.2 AI/ML の統合、1.3 ハイブリッド）
- 自分の解答：A（不正解）

> **SAP-C03 での重要度は低め**：AWS IoT のサービス（IoT Core、IoT Greengrass など）は SAP-C03 の出題範囲から外れた。
> ただし「クラウドで学習 → 現場で推論」「切断中はためて、つながったら送る」という考え方は、Outposts など他のエッジの問題にも通じる。

## 問題の要約（自分の言葉で）

ネット回線が不安定な農地（数時間〜数日切れる）にある装置で、カメラ画像から作物の病気を判定したい。
モデルは SageMaker AI で学習し、新しい版を定期的に現場へ配る。切断中も判定を続け、つながったら結果をクラウドへ集める。

## 要件のキーワード

- 「数時間〜数日切れる」「切断中も判定を継続」→ 推論はクラウドではなく **現場（エッジ）** で動かす
- 「更新版を定期的に配布」→ 現場の機器へソフトやモデルを配る仕組みが必要
- 「復旧後に結果を集約」→ 現場にためておき、つながったら送る

## 正解

- B：AWS IoT Greengrass でモデルと推論コードを現場に配り、現場で推論。結果はためておいて、つながったら送る

## なぜ正解？

- **Greengrass** は、現場の機器（ゲートウェイ）で AWS のソフトを動かす仕組み。SageMaker AI で学習したモデルを「コンポーネント」として配って、更新も遠隔でできる
- 推論が現場で完結するので、ネットが切れても判定は止まらない
- **ストリームマネージャー**は、データを現場にためておき、つながったら自動でクラウドへ送る機能。送れなかった分は再送を繰り返す

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| A：画像をクラウドに送り、SageMaker AI の推論エンドポイントで判定 | 推論がクラウドにあるので、**ネットが切れている間は判定できない**。画像をためて後で送っても、判定は「切断中も継続」にならない |
| C：Systems Manager でモデルを配り、CloudWatch Logs エージェントで結果をためる | Systems Manager はサーバー管理の道具で、モデルを動かして推論する仕組みはない。モデルの更新と推論の実行をまとめて面倒見てくれるのは Greengrass |
| D：現場に Snowball Edge を置き、結果は機器ごと AWS に送り返す | Snowball Edge は一時的な大容量データ移行やエッジ処理向けの物理機器。結果を集めるのに **機器を返送** するのは遅すぎるし、モデルの定期更新にも向かない |

## 自分が A を選んだ理由と反省

「ローカルディスクにバッファして、回復後にまとめてアップロード」の一文で、切断対策ができていると思ってしまった。
でも要件は「切断中も **判定を継続**」。ためているのは画像で、**判定（推論）はクラウドでしかできない**。
→ 「データをためられるか」ではなく「**処理がどこで動くか**」を確認する。

## 補足：選択肢 B の細かい不正確さ

公式ドキュメントでは、ストリームマネージャーの送り先は Kinesis Data Streams、S3、IoT SiteWise。
選択肢の「ストリームマネージャーで IoT Core へ送る」は厳密には違う。ただ、他の3つは要件そのものを満たさないので、答えは B で変わらない。

## 調べたこと

- [Greengrass で機械学習の推論を行う](https://docs.aws.amazon.com/greengrass/v2/developerguide/perform-machine-learning-inference.html)：SageMaker AI などで学習したモデルを、コンポーネントとして現場の機器に配って推論できる
- [ストリームマネージャーの送り先](https://docs.aws.amazon.com/greengrass/v2/developerguide/stream-export-configurations.html)：Kinesis Data Streams、S3、IoT SiteWise。失敗したら最大5分間隔で再送し続ける

## 一言で言うと

- 「ネットが切れても処理を続ける」→ **処理を現場で動かす**。クラウドの推論エンドポイントは選ばない
- 「ためて後で送る」だけでは足りない。**何を**ためているか（データか結果か）を見る
