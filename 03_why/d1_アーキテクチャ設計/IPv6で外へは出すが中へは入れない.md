# IPv6 で、外へは出すが中へは入れない

- 出典：CloudTech SAP-2009（カテゴリ：分野1-ネットワーク接続戦略）
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.4 ネットワーク：**IPv6 は SAP-C03 で追加された内容**）
- 自分の解答：3番目（正解）

## 問題の要約（自分の言葉で）

プライベートサブネットのバッチ用 EC2 が、外部のリポジトリから更新パッケージを取ってくる。
システム全体を IPv6 にするので、EC2 には IPv6 アドレスを付けて外と通信する。外へ出るのは OK、インターネット側から始まる通信はすべて入れない。

## 要件のキーワード

- 「IPv6」「外へ出るのは OK、外からは入れない」→ **Egress-Only インターネットゲートウェイ**

## 正解

- 3番目：VPC に IPv6 の CIDR を付け、プライベートサブネットと EC2 にも IPv6 を割り当てる。**Egress-Only インターネットゲートウェイ** をアタッチし、プライベートサブネットのルートテーブルで ::/0 をそこへ向ける

## なぜ正解？

- IPv6 のアドレスはすべて **グローバル（インターネットから直接届くアドレス）** なので、IPv4 のように NAT でアドレスを隠す必要がない
- その代わり「中から始めた通信の返事だけ通し、外から始まる通信は止める」役が必要。それが **Egress-Only インターネットゲートウェイ**（IPv6 版の NAT ゲートウェイのような位置づけ）

## IPv4 と IPv6 の対応

| やりたいこと | IPv4 | IPv6 |
| --- | --- | --- |
| 外へも出る、外からも入れる | インターネットゲートウェイ | インターネットゲートウェイ |
| 外へは出る、外からは入れない | NAT ゲートウェイ | **Egress-Only インターネットゲートウェイ** |

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| 1番目：IPv6 の ::/0 を NAT ゲートウェイへ向ける | NAT ゲートウェイは IPv4 のアドレス変換のためのもの。IPv6 の外向き通信を ::/0 で受ける役ではない |
| 2番目：インターネットゲートウェイへ向け、セキュリティグループで外からの通信を止める | 経路としては **外から入れる状態** のまま。セキュリティグループの設定ひとつに頼ることになり、「すべて到達させない」を構成で保証できない |
| 4番目：NLB をデュアルスタックで作り、::/0 を NLB へ向ける | NLB は外からの通信を受けて振り分けるもので、外へ出る通信の出口にはならない。ルートテーブルの行き先にも指定できない |

## 一言で言うと

- IPv6 で「出るだけ」→ **Egress-Only インターネットゲートウェイ**
- IPv4 の NAT ゲートウェイの役を、IPv6 では Egress-Only が担う
