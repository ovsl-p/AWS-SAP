# プライベートホストゾーンの名前が引けない、パブリック DNS 名も付かない

- 出典：CloudTech SAP-2004（カテゴリ：分野1-ネットワーク接続戦略）
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.4 ネットワーク）
- 自分の解答：B（正解。ただし根拠がなく、まぐれ）

## 問題の要約（自分の言葉で）

オンプレと Direct Connect でつながった VPC で、AWS の DNS（AmazonProvidedDNS）を使っている。
社内用の名前のために Route 53 のプライベートホストゾーンを作ったが、EC2 から名前を引いても応答がない。
さらに、パブリック IP を持つインスタンスにパブリック DNS 名が付いていない。両方を直すには？

## 要件のキーワード

- 「プライベートホストゾーンの名前が引けない」→ VPC との **関連付け** と、VPC の **DNS 属性2つ** を確認
- 「パブリック DNS ホスト名が付いていない」→ **enableDnsHostnames** が無効になっている
- 「AWS が提供する DNS を使う構成」→ DHCP オプションセットは **AmazonProvidedDNS** のまま

## 正解

- B：プライベートホストゾーンを VPC に関連付け、**enableDnsSupport と enableDnsHostnames の両方を有効**にする。DHCP オプションセットは AmazonProvidedDNS（VPC CIDR の先頭 **+2** にある Route 53 Resolver）

## なぜ正解？

VPC の DNS 属性は2つあり、役割が違う。

| 属性 | 役割 | 無効だと |
| --- | --- | --- |
| enableDnsSupport | VPC の中で AWS の DNS（Route 53 Resolver）を使えるようにする | VPC 内で名前解決ができない |
| enableDnsHostnames | パブリック IP を持つインスタンスに **パブリック DNS 名** を付ける | パブリック DNS 名が付かない |

- **プライベートホストゾーンを使うには、両方が有効（true）である必要がある**。片方だけではダメ
- enableDnsHostnames は、**デフォルト VPC 以外では最初から無効（false）**。自分で作った VPC だと、ここでつまずきやすい
- これで2つの問題（名前が引けない、パブリック DNS 名がない）が同時に解決する

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| A：DHCP オプションセットの DNS をオンプレの DNS にし、インバウンドエンドポイントを使う。enableDnsHostnames は最初から有効 | EC2 がオンプレの DNS に問い合わせるようになり、**プライベートホストゾーンを見に行かなくなる**。インバウンドエンドポイントは「オンプレ → AWS」向きの入口で、向きが逆。enableDnsHostnames はデフォルト VPC 以外では最初は **無効** なので「変更不要」も誤り |
| C：enableDnsSupport だけ有効にし、resolv.conf に CIDR の先頭 **+1** を書く | プライベートホストゾーンには **両方** の属性が必要。先頭 +1 は VPC のルーター用で、DNS は **+2** |
| D：パブリックホストゾーンを作り、アウトバウンドエンドポイントでオンプレの DNS へ転送 | 社内用の名前をパブリックホストゾーンに置くと **インターネットに公開** されてしまう。オンプレの DNS はそのドメインを持っていないので転送しても答えは返らない。パブリック DNS 名は Elastic IP では付かず、enableDnsHostnames が必要 |

## まぐれだった点の整理

次の3つを知っていれば、根拠を持って B を選べる。

1. プライベートホストゾーンには **enableDnsSupport と enableDnsHostnames の両方** が必要
2. パブリック DNS 名を付けるのは **enableDnsHostnames**（デフォルト VPC 以外は最初は無効）
3. VPC の DNS（Route 53 Resolver）は **CIDR の先頭 +2**（169.254.169.253 でも届く）。+1 はルーター

## Route 53 Resolver のエンドポイントの向き

| エンドポイント | 向き | 使う場面 |
| --- | --- | --- |
| インバウンド | オンプレ → AWS | オンプレからプライベートホストゾーンの名前を引きたい |
| アウトバウンド（＋転送ルール） | AWS → オンプレ | VPC からオンプレの社内ドメインの名前を引きたい |

## 調べたこと

- [VPC の DNS 属性](https://docs.aws.amazon.com/ja_jp/vpc/latest/userguide/AmazonDNS-concepts.html)：
  - Route 53 Resolver は VPC の CIDR の **+2** と 169.254.169.253 にある
  - enableDnsHostnames は **デフォルト VPC でない限り false** が初期値
  - プライベートホストゾーンを使う場合は **両方の属性を true** にする
- [プライベートホストゾーンの考慮事項](https://docs.aws.amazon.com/ja_jp/Route53/latest/DeveloperGuide/hosted-zone-private-considerations.html)：同じく、両方の属性を true にする必要がある

## 一言で言うと

- プライベートホストゾーンが引けない → **VPC に関連付け ＋ DNS 属性を2つとも有効**
- VPC の DNS は **+2**。+1 はルーター
