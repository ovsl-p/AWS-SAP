# 専用線を足しても、インターネット向けの経路は変えない

- 出典：CloudTech SAP-2001
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.3 ハイブリッド、1.4 ネットワーク）
- 自分の解答：D（不正解）

## 問題の要約（自分の言葉で）

プライベートサブネットのアプリが NAT ゲートウェイ経由で外部 API を呼んでいる VPC に、オンプレとの専用線を追加したい。
オンプレの CIDR は複数あり、今後も増える。インターネット向けの経路は今のまま残す必要がある。

## 要件のキーワード

- 「専用線」→ Direct Connect（VPN ではない）
- 「CIDR が複数・将来増える」→ 静的ルートの手作業ではなく、BGP で自動的に経路を受け取る
- 「インターネット向けは同じ経路」→ 0.0.0.0/0 には触らない

## 正解

- B：Direct Connect のプライベート VIF ＋ 仮想プライベートゲートウェイ（VGW）＋ ルート伝播

## なぜ正解？

- **プライベート VIF** は VPC の中（プライベート IP）とつなぐための接続。オンプレのサーバーと話すならこれ
- **ルート伝播**を有効にすると、オンプレが BGP で広告した CIDR がルートテーブルに自動で入る。CIDR が増えても作業不要
- ルートテーブルは **一番細かい（プレフィックスが長い）ルートが優先**される。オンプレの CIDR（例：10.1.0.0/16）は 0.0.0.0/0 より細かいので、オンプレ宛てだけが専用線へ流れ、それ以外は今までどおり NAT ゲートウェイへ行く

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| A：パブリック VIF ＋ 0.0.0.0/0 を VGW へ | パブリック VIF は S3 など AWS の公開サービス用で、VPC 内とはつながらない。しかも 0.0.0.0/0 を VGW に向けると、インターネット向けの通信まで奪ってしまう（デフォルトルートは1本しか置けない） |
| C：Site-to-Site VPN ＋ 静的ルート | VPN はインターネット越しなので「専用線」ではない。静的ルートなので CIDR が増えるたびに手作業になる |
| D：プライベート VIF ＋ Transit Gateway ＋ 静的ルートを手で登録 | ①Transit Gateway につなぐには **トランジット VIF**（Direct Connect ゲートウェイ経由）が必要で、プライベート VIF では直接つなげない。②CIDR が増えるたびに手で更新するので「将来の追加」に弱い |

## 自分が D を選んだ理由と反省

「Transit Gateway ＝ 拡張性が高い」という連想で選んだ可能性が高い。
でも問題の「拡張性」は **CIDR が増えること** であって、**VPC が増えること** ではなかった。VPC は1つだけなので Transit Gateway は不要。

## Direct Connect の VIF の使い分け

| VIF の種類 | つなぐ先 | 使う場面 |
| --- | --- | --- |
| プライベート VIF | VGW（または Direct Connect ゲートウェイ経由で複数の VGW） | VPC 内のサーバーと通信 |
| トランジット VIF | Direct Connect ゲートウェイ経由で Transit Gateway | 多数の VPC とまとめて通信 |
| パブリック VIF | AWS の公開エンドポイント（S3、DynamoDB など） | インターネットを通らずに AWS の公開サービスを使う |

## 調べたこと

- [Direct Connect の仮想インターフェイス](https://docs.aws.amazon.com/ja_jp/directconnect/latest/UserGuide/WorkingWithVirtualInterfaces.html)：VIF は3種類（プライベート、パブリック、トランジット）
- [ルートテーブルの優先順位](https://docs.aws.amazon.com/ja_jp/vpc/latest/userguide/VPC_Route_Tables.html#route-tables-priority)：一番細かいルート（最長一致）が優先される

## 一言で言うと

- 1つの VPC ＋ 専用線 ＋ CIDR が増える → **プライベート VIF ＋ VGW ＋ ルート伝播**。0.0.0.0/0 は触らない
- Transit Gateway が出てきたら「**VPC がたくさんあるか？**」を確認。VPC が1つなら過剰
