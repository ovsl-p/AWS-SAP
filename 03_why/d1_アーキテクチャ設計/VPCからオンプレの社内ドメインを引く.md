# VPC からオンプレの社内ドメインの名前を引く

- 出典：CloudTech SAP-2005（カテゴリ：分野1-ネットワーク接続戦略）
- 日付：2026-11-14
- 分野：1 アーキテクチャ設計（タスク 1.3 ハイブリッド、1.4 ネットワーク）
- 自分の解答：D（不正解）
- 関連：[プライベートホストゾーンの名前が引けない](プライベートホストゾーンの名前が引けない.md)（SAP-2004。こちらは逆向き）

## 問題の要約（自分の言葉で）

複数の VPC とオンプレが Direct Connect でつながっている。オンプレには社内ドメイン（corp.example.com）を管理する DNS サーバーが2台ある。
VPC 内の EC2 から、その社内ドメインの名前を引きたい。VPC 側は今までどおり Amazon の DNS を使い続けたい。

## 要件のキーワード

- 「VPC → オンプレのドメインを引く」→ 向きは **AWS → オンプレ** なので **アウトバウンド** エンドポイント
- 「Amazon 提供の DNS を引き続き利用」→ DHCP オプションセットや resolv.conf は変えない
- 「オンプレの DNS サーバーが管理」→ ゾーンはオンプレに置いたまま、**問い合わせを転送** する

## 正解

- C：Route 53 Resolver の **アウトバウンドエンドポイント** を複数 AZ に作り、corp.example.com 宛ての **転送ルール** でオンプレの DNS サーバー2台を指定。ルールを VPC に関連付ける

## なぜ正解？

- EC2 はいつもどおり Amazon の DNS（Route 53 Resolver）に問い合わせる
- Resolver は転送ルールを見て、corp.example.com だけをアウトバウンドエンドポイント経由でオンプレの DNS へ回す。それ以外の名前は今までどおり Amazon の DNS が答える
- ゾーンはオンプレに置いたままなので、オンプレ側でレコードを変えればすぐ反映される
- 転送ルールは RAM で共有できるので、**複数の VPC** にも同じルールを使える

## なぜ他はダメ？

| 選択肢（要点） | ダメな理由 |
| --- | --- |
| A：インバウンドエンドポイントを作り、その IP を EC2 の resolv.conf に書く | インバウンドは **オンプレ → AWS** 向きの入口で、向きが逆。resolv.conf を書き換えるのは「Amazon の DNS を使い続ける」にも反するし、EC2 ごとの手作業になる |
| B：DHCP オプションセットの DNS をオンプレの DNS サーバーにする | 社内ドメインは引けるようになるが、**VPC の DNS がオンプレに切り替わる**ので「Amazon の DNS を使い続ける」に反する。プライベートホストゾーンや AWS 内部の名前も引けなくなるおそれがある |
| D：プライベートホストゾーンにオンプレのゾーンを丸ごとコピーし、DMS で定期的に同期 | **DMS はデータベースの移行サービスで、DNS のゾーンは同期できない**。同じゾーンを2か所で持つと、ずれが起きて管理が大変になる |

## 自分が D を選んだ理由と反省

「プライベートホストゾーンに入れれば VPC から引ける」は正しいが、**同期の手段に DMS** が出てきた時点で不自然だった。
→ サービス名が出てきたら、**そのサービスの本来の役割**（01_glossary の一言）と合っているか確認する。DMS は「DB を止めずに移行」。

## SAP-2004 とセットで覚える

| やりたいこと | 向き | 使うもの |
| --- | --- | --- |
| VPC から **オンプレのドメイン** を引く（この問題） | AWS → オンプレ | アウトバウンドエンドポイント ＋ 転送ルール |
| オンプレから **プライベートホストゾーン** を引く | オンプレ → AWS | インバウンドエンドポイント（オンプレの DNS から条件付き転送） |
| VPC から **プライベートホストゾーン** を引く（SAP-2004） | VPC 内 | VPC に関連付け ＋ DNS 属性を2つとも有効 |

## 一言で言うと

- VPC から外（オンプレ）の名前を引く → **アウトバウンド ＋ 転送ルール**。DHCP や resolv.conf は触らない
- 選択肢に場違いなサービス（DNS の同期に DMS など）が出てきたら、それだけで外せる
